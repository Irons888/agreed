# Test set

Small, reproducible recordings with expected results. The scripts and every `expected.json` were written and committed **before any product code existed**. The git history shows that order.

| Case | What it is | What it checks | Expected outcome |
|---|---|---|---|
| T1-main | Anna (PM) and Mark (backend) before a client launch. They introduce themselves | All five required cases: a proposal never accepted, an accepted task, a corrected deadline, a cancelled task, a task with no named owner. Plus one unresolved question | Result: 3 agreed tasks, 1 open question, dark mode not accepted, meeting room cancelled. Weekdays stay as spoken because the recording has no date |
| T2-changed | T1 with one agreement changed: Anna accepts dark mode | The product follows the audio, not a prepared answer | Same as T1, except dark mode is agreed (Mark, “by Friday”) |
| T3-ambiguous | Two people who never say their names, and every statement is hedged | Asking instead of guessing | Clarification for speaker names. No agreed tasks, no owners, no dates |
| T4-dated | The date is said out loud at the start | Relative dates are resolved only from the recording | “tomorrow” → 2026-10-06, “by Friday” → 2026-10-09 |
| T5-three-voices | Three people on the call | Out-of-scope input | Decline: three voices detected, the prototype supports two |
| T6-noisy | T1 over a noisy phone line (300–3400 Hz, pink noise) | Robustness | Same as T1 |

## Files in each case

- `script.json` — what is said, line by line. T2 only lists the lines it replaces in T1.
- `expected.json` — the expected result, written by hand from the script.
- `audio.wav` — the recording: 16 kHz, mono.
- `timeline.json` — when each line starts and ends, in seconds.
- `script.md` — readable script with times.

The last three files are generated by `build.mjs`.

## How the audio is made

```bash
cp testset/.env.example testset/.env   # add ELEVENLABS_API_KEY
npm run testset:voices            # optional: list available voices
npm run testset:build             # all cases, or: node testset/build.mjs T1-main
```

- Each line is synthesized separately with ElevenLabs and joined with short pauses. That is why `timeline.json` knows exactly where each line starts and ends.
- Lines are cached by voice and text, so T1 and T2 are byte-identical apart from the replaced lines.
- T6 is made from the T1 audio with ffmpeg.
- Voices used are recorded in `voices.resolved.json`.

Voices: ElevenLabs text-to-speech. The audio is synthetic. That keeps it shareable and lets anyone regenerate it from the scripts. Its limitation is clean studio audio, which is why T6 exists.

## How `expected.json` is read

- `outcome`: `result`, `clarify` (the product should ask before concluding) or `decline` (it should refuse and explain).
- `items[].keys`: words that identify the item in the product's title or quote.
- `items[].status`: one status, or a list of statuses that are all acceptable. `agreed` is never in such a list.
- `items[].owner.name`: `null` means the product must show no owner.
- `items[].deadline`:
  - `raw_contains` — the wording that must be kept;
  - `date` — a calendar date, only when the recording states its own date;
  - `changed_from_contains` — the earlier deadline that was replaced.
- `items[].evidence_lines`: the script lines that support the item. The quote's time must overlap them in `timeline.json`.
- `items[].optional`: the item may be absent, but if present it must have an allowed status.
- `traps`: what the product must not do. Anything outside `items` counts as an unsupported extra.
